## This week adds

The generation loop: roll one prompt more than once, choose among the rolls,
and log the seed that made the one you kept.

```notes
Every generator this course touches runs the same loop underneath whatever
interface sits on top of it: set some parameters, generate, look at what came
back, decide whether to keep it, and either stop or go again.
```

## Rolling is not re-prompting

A generator is a sampler, not an oracle. The same prompt with a different
draw returns a genuinely different result.

<LadderStill week={2} tier="t1" />

```notes
Running the same prompt more than once is called rolling, and it is not a
sign the first attempt failed — it's the default way this loop is used. A
generator is a sampler, not an oracle: the same prompt with a different
random draw produces a genuinely different result, and the skill this course
credits is choosing well among several rolls, not writing a prompt so precise
it only needs one. Selection is the actual job. Generation is just what makes
selection possible.
```

## The seed as an address

A seed is not a style knob. On the same model and settings it returns to the
same result, so a seed plus its parameters is what specifies a roll.

<LadderStill week={2} tier="t4" />

```notes
A generation seed is not a style knob; it's an address. On the same model,
sampler, and software version, the same seed with the same parameters returns
to the same result, which means a seed plus its full parameter list is the
only thing that actually specifies a roll. Change one parameter and keep the
seed, and a specific variable is being tested in isolation; change the seed
and a different roll has been generated regardless of what else stayed the
same. Log both, every time, or the roll that looked right yesterday is
unfindable tomorrow.
```

---

## The production log

A roll without a log is a lucky accident the moment the tab closes. Name the
graph, the seed, and every parameter that could change the output.

```notes
The log is not paperwork attached to the work; it is the record that turns a
good roll into a repeatable one. A usable log names the workflow graph in
use, the seed, and every parameter that could plausibly change the output —
enough that someone who wasn't in the room could load the same graph and land
on a comparable result. A roll without a log is a lucky accident the moment
the tab closes.
```

## The ladder

Five rolls of one prompt. Nothing changes between them but the draw.

1. Roll one — seed 66740
2. Roll two — seed 66741
3. Roll three — seed 66742
4. Roll four — seed 66743
5. Roll five — seed 66744

```notes
This week's ladder runs sideways rather than up, because the skill being
graded is selection, not escalating difficulty. The exercise is five rolls of
exactly one prompt, on the graph the course supplies, with nothing changed
between them but the random draw. Each of the five gets its own checklist
verdict against the same four checks — hands, physics, text in frame, and
overall framing — logged as pass or fail rather than a general impression.
Climbing this ladder means getting more of the five to clear the checklist,
and being able to say precisely which check failed on the ones that didn't.
```
